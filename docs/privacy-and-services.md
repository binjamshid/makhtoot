# Privacy and services

Makhtoot keeps projects on the device and has no Makhtoot account or application backend. The bilingual privacy policy covers iOS and iPadOS. This guide describes the behavior and configuration visible in the repository, including the Android port under development. [Privacy policy](legal/privacy.html)

## iPhone and iPad

**Local projects.** The app stores `.makhtoot` packages in its managed project library. A package contains the project manifest, scene and any included assets or thumbnail. Editing, saving, using bundled fonts and exporting use local files. When you share an export or copy a project out through Files, you choose where that copy goes. [Project library implementation](../Makhtoot/AppShell/Persistence/MKPersistenceProjectLibrary.swift), [editor sharing](../Makhtoot/AppShell/Scenes/Editor/EditorScene.swift)

**Project sync.** Project sync defaults to off. The app keeps the user's choice on the device across relaunches. The controller checks the choice and cloud-sync entitlement before checking the iCloud account or starting the project engine. With consent and an eligible entitlement, the engine uses the private database in the user's iCloud account for project titles, folder identifiers, manifests, scenes, thumbnails, assets, and change metadata. Entitlement loss pauses sync and preserves the choice. Turning sync off stops new sync activity and requests cancellation of in-progress transfers. Previously synced copies may remain in iCloud. [CloudKit schema](../MakhtootKit/Sources/MKSync/Docs/CloudKitSchema.md), [app startup](../Makhtoot/AppShell/AppContainer.swift), [sync controller](../MakhtootKit/Sources/MKSync/Engine/MKSyncEngineController.swift), [sync settings](../Makhtoot/AppShell/Scenes/Settings/SyncSettingsView.swift), [privacy policy](legal/privacy.html)

**Font-usage analytics.** Collection defaults to off. Settings → Privacy records consent locally. With consent, the analytics service can count font use on device and upload batches to the app's CloudKit public database. The app-supplied payload consists of a random batch ID, ISO week, major.minor app version, and pairs of font ID and count range. Project contents, font files, and persistent user or device identifiers are outside the payload. Revoking consent disables subsequent collection and clears local counters when the revocation saves. The startup and consent paths are wired in this checkout. The editor has no call to record font use here. Any editor integration should restrict recording to bundled fonts, as described in the policy. [Consent manager](../MakhtootKit/Sources/MKAnalytics/Consent/MKConsentManager.swift), [upload payload](../MakhtootKit/Sources/MKAnalytics/Upload/MKFontUsageBatch.swift), [app startup](../Makhtoot/AppShell/AppContainer.swift)

**Purchases and trial.** Apple processes purchases and restores through StoreKit 2. Makhtoot verifies entitlement on device. The app-side trial keeps its timing record in Keychain and can mirror the record to the user's iCloud key-value store independently of project sync and analytics consent. The record contains trial timing and clock observations, trial extension days, a format version, and a random record identifier. [StoreKit entitlement resolver](../MakhtootKit/Sources/MKStore/MKEntitlementResolver.swift), [trial manager](../MakhtootKit/Sources/MKStore/Trial/MKTrialManager.swift), [trial record fields](../MakhtootKit/Sources/MKStore/Trial/MKTrialRecord.swift)

**Fonts.** The checked-in configuration bundles premium fonts and gates access by entitlement. A hosted mode exists in source for downloading fonts over HTTPS, with an intentionally invalid placeholder URL. [Font delivery configuration](../MakhtootKit/Sources/MKFonts/MKPremiumDelivery.swift)

## Android

The checked-in port has service interfaces and stubs for Drive project sync, Play Billing and analytics. It has no launcher activity in its application manifest. The design calls for Android-to-Android premium project sync through the user's Google Drive `appDataFolder`, purchases through Google Play, and a no-op analytics uploader by default. Signing up for those services alone cannot make the port functional. [Android manifest](../android/app/src/main/AndroidManifest.xml), [sync controller](../android/mk-sync/src/main/kotlin/net/binjamshid/makhtoot/mk/sync/engine/MkSyncEngineController.kt), [purchase controller](../android/mk-store/src/main/kotlin/net/binjamshid/makhtoot/mk/store/MkPurchaseController.kt), [analytics service](../android/mk-analytics/src/main/kotlin/net/binjamshid/makhtoot/mk/analytics/service/MkAnalyticsService.kt), [Android decisions](../FOUNDATION.md)

Android's checked-in backup and device-transfer rules allow only the trial state file. They exclude project files and analytics counters. The trial manager is still a stub. [Backup rules](../android/app/src/main/res/xml/backup_rules.xml), [data extraction rules](../android/app/src/main/res/xml/data_extraction_rules.xml), [trial manager](../android/mk-store/src/main/kotlin/net/binjamshid/makhtoot/mk/store/trial/MkTrialManager.kt)

## Fork configuration

Use your own signing identity, bundle or application ID, support address and policy URLs for an independently distributed fork. Keep credentials, signing files and private configuration out of publicly shared source. Use placeholders where readers need configuration examples. [iOS entitlements](../Makhtoot/Config/Makhtoot.entitlements), [Android app configuration](../android/app/build.gradle.kts), [iOS legal links](../MakhtootKit/Sources/MKAnalytics/MKLegalLinks.swift), [license](../LICENSE)

| Service | What the fork needs |
|---|---|
| iOS project sync | An iCloud container provisioned for the fork. Set the container consistently in `Makhtoot.entitlements` and `MKSyncSchema.swift`, then configure the private-database schema. To omit sync, skip the CloudKit controller bootstrap and omit its capability unless another feature uses it. [Sync schema](../MakhtootKit/Sources/MKSync/Schema/MKSyncSchema.swift), [app startup](../Makhtoot/AppShell/AppContainer.swift) |
| iOS analytics | A CloudKit public-database schema in the fork's default container, with permissions appropriate for the upload and configuration records. To omit analytics, keep recording and upload disabled and use an inert database implementation. [Analytics schema](../MakhtootKit/Sources/MKAnalytics/Docs/AnalyticsSchema.md), [database interface](../MakhtootKit/Sources/MKAnalytics/Upload/MKCloudKitPublicDatabase.swift) |
| iOS StoreKit and trial | For live purchases, create the fork's App Store Connect products and update its StoreKit product IDs. The local StoreKit configuration supports purchase-path testing. To keep trial state local, use a local trial store without the iCloud key-value mirror. [Product IDs](../MakhtootKit/Sources/MKStore/MKStoreIDs.swift), [local StoreKit configuration](../Makhtoot/Config/Makhtoot.storekit), [trial manager](../MakhtootKit/Sources/MKStore/Trial/MKTrialManager.swift) |
| Hosted fonts | Keep bundled delivery for offline use. If you enable hosted delivery, supply a catalog and a static HTTPS host for font files cleared for that distribution. [Font delivery configuration](../MakhtootKit/Sources/MKFonts/MKPremiumDelivery.swift) |
| Android services | Complete the service implementations first. A Drive sync integration would use the fork's Google Cloud project and OAuth configuration for its application and signing identities. A Play Billing integration would use products registered for the fork's app in Play Console. Keep analytics transport inert until a separately configured and disclosed service is available. [Android decisions](../FOUNDATION.md), [Android app configuration](../android/app/build.gradle.kts) |

The iOS analytics tests use a spy database to exercise consent, upload gating and payload fields without a CloudKit account. The sync tests exercise the saved choice, entitlement gate, a delayed account response after opt-out, and conflict decisions using local fixtures. For device checks, use the fork's development configuration and disposable projects. Verify sync and analytics over launch, opt-in and opt-out, including relaunch after disabling sync, before describing the fork's behavior in its privacy policy. [Build instructions](BUILD.md), [analytics tests](../MakhtootKit/Tests/MKAnalyticsTests), [sync tests](../MakhtootKit/Tests/MKSyncTests)

## 5. Deviations (logged, not silently worked around)

1. **File-based JSON persistence instead of SwiftData.** T1/T2 imply recording-layer storage. Using SwiftData `@Model` classes for consent records and counters would require `MKPersistence`'s `ModelContainer` to be aware of `MKAnalytics` model types, introducing a circular dependency risk (MKPersistence imports MKFoundation; MKAnalytics imports MKFoundation; if MKPersistence also imported MKAnalytics there would be a cycle). Resolved by using plain JSON file persistence in `MKAnalyticsStorage.analyticsDirectory()` (separate directory from MKPersistence). Logged here; no impact on D-125 compliance (file stays on device, never uploaded).

2. **`MKFontUsageRecording` protocol uses `String` not `MKFontID`.** `MKFontID` is defined as `public typealias MKFontID = String` in `MKFonts/MKFontTypes.swift`. Moving it to `MKFoundation` would: (a) break every `MKFonts` source that uses `MKFontID` without an explicit `import MKFoundation`; (b) cause ambiguity in test files that import both `MKFoundation` and `MKFonts`. Resolved by leaving `MKFontID` in `MKFonts` and using `String` directly in `MKFontUsageRecordingProtocol.swift` with an explanatory comment. Since `MKFontID = String` is a transparent typealias, Swift resolves conformances by type identity — call sites passing `MKFontID` values satisfy `String` parameters without any cast.

3. **SyncSettingsView is a stub.** T9 requires a sync section; WS-11 (MKSync) is still in progress by the parallel agent. `SyncSettingsView` shows a single Arabic section header with a placeholder "coming soon" row and a `// WS-11 deferred` comment. Will be replaced by the WS-11 session.

4. **`MKFeatureFlags.analyticsEnabled` is a supplementary, not a replacement, kill switch.** T5 specifies two remote/local kill-switch layers; the compile-flag layer (D-207 layer 3) is added as `MKFeatureFlags.analyticsEnabled` (`MKFoundation`) defaulting to `true`. This is stricter than the packet's minimum requirement.

5. **`MKAnalyticsService.lastRecordedWeek` uses ISO week of last recorded date, not a separate stored value.** Computed directly from `lastRecordedAt` rather than maintaining a redundant field; semantically equivalent.

## 6. D-125 compliance checklist

| Constraint | Status |
|---|---|
| No text content | Analytics records only `fontID` (opaque string identifier) and an integer count — never text content, project names, or user input. |
| No project references | Payload schema: `batchID`, `week`, `appVersion`, `entries` (fontID + bucket) only. No project IDs, record IDs, or user IDs. |
| No device identifiers | `CKRecord` saved to CloudKit **public** database — no user token or device fingerprint. |
| No fine-grained timestamps | ISO week string only (`"2026-W29"` format). Date-of-consent is stored locally but never uploaded. |
| No font files | Only the opaque `fontID` string (e.g., `"amiri"`) and a bucket string (e.g., `"5-9"`) are included. |
| Consent default OFF | `MKConsentManager.isConsentGranted` returns `false` for `.neverAsked` and `.revoked` cases. Nothing is recorded or uploaded before consent. |
| Three-layer kill switch | (1) `MKConsentManager.isConsentGranted` local check; (2) `fetchAnalyticsConfig()` remote `MKAnalyticsConfig` CloudKit record; (3) `MKFeatureFlags.analyticsEnabled` compile-time flag. |
